## Authentication

### Critical
- [ ] **Auth tokens stored in Zustand persist (localStorage) not HTTP-only cookies** (`apps/web/src/stores/authStore.ts`). The API client uses `js-cookie` for token injection (`apps/web/src/lib/api.ts`), but tokens are also persisted in zustand's localStorage. This creates two sources of truth and exposes tokens to XSS.

### High
- [ ] **No input validation on registration** (`apps/api/src/routes/auth.ts`). Password strength (length, complexity), email format, and name validation are not enforced server-side. Accepts any string as password.
- [ ] **Anonymous mode creates user but doesn't sync to backend** (`apps/web/src/stores/authStore.ts:35-40`). Anonymous users get a user object in localStorage but no backend session — they can't persist data across sessions or devices.

### Medium
- [ ] **Token refresh endpoint accepts refresh token from body OR cookie inconsistently** (`apps/api/src/routes/auth.ts`). The refresh middleware checks `req.body.refreshToken` first, then falls back to cookies. The frontend only sends it in the body.
- [ ] **Logout doesn't invalidate tokens server-side** (`apps/api/src/routes/auth.ts`). Tokens remain valid until expiry. There's no token blacklist.

## Workspaces

### High
- [ ] **Workspace page doesn't fetch collections or environments on mount** (`apps/web/src/app/(app)/workspace/page.tsx:92-108`). `loadInitialData` only fetches `/api/workspaces`. Collections and environments are never fetched from the server — they rely entirely on Zustand's persisted localStorage state.

### Medium
- [ ] **No workspace switcher in UI despite API supporting multiple workspaces** (TopBar, Sidebar). The UI only uses `currentWorkspace` but there's no dropdown/menu to switch between workspaces.
- [ ] **No loading state for workspace page initial data** (`page.tsx:92-108`). User sees empty state until data loads.

## Collections & Folders

### Critical
- [ ] **Collection creation defaults workspaceId to "default" string** (`apps/api/src/routes/collections.ts:60`). `const finalWorkspaceId = workspaceId || 'default'` — when workspaceId is missing from request body, it falls back to literal `'default'` instead of returning a validation error or looking up the user's active workspace.
- [ ] **Collection restore sets `deletedAt: undefined` which doesn't remove field in CouchDB** (`apps/api/src/routes/collections.ts:205`). CouchDB's nano library treats `undefined` as no-op on update, so the `deletedAt` field persists. Must use `db.insert` or `_deleted` field to properly restore.
- [ ] **TrashItem is created on delete but never cleaned up on restore** (`apps/api/src/routes/collections.ts:166-176` vs `191-219`). Delete creates a `TrashItem` document but restore doesn't delete/remove the corresponding trash entry.

### High
- [ ] **Folder deletion only handles direct children, not nested folders** (`apps/web/src/app/(app)/workspace/page.tsx:231-238`). `handleDeleteFolder` only filters folders at the current level — nested sub-folders under the deleted folder are orphaned.
- [ ] **`moveItem` function only handles 2 levels of folder nesting** (`apps/web/src/stores/collectionsStore.ts:353-435`). The move logic in collectionsStore explicitly only processes `folders[].folders[]` (2 levels) and ignores deeper nesting.

### Medium
- [ ] **Folder creation response returns new folder object but doesn't include it in collection's folders array on API response** (`apps/api/src/routes/collections.ts:265-275`). The API returns just the folder, not the updated collection.
- [ ] **No validation that a folder with same name doesn't already exist** at the same level in a collection.

## Requests & Execution

### Critical
- [ ] **Request creation defaults workspaceId to "default" string** (`apps/api/src/routes/requests.ts:18`). Same pattern as collections — `const finalWorkspaceId = workspaceId || 'default'`.

### High
- [ ] **Pre-request script execution doesn't affect the actual request** (`apps/web/src/app/(app)/workspace/page.tsx:454-457`). The script runs with a `pm.request` object but modifications to it aren't reflected in the `currentRequest` state or the actual API call that follows.
- [ ] **`handleSendAndDownload` duplicates the entire auth header construction and request building logic** (`page.tsx:532-568`). ~50 lines of code duplicated from `handleSendRequest` (460-479) with subtle differences (e.g., uses direct `fetch` instead of `apiClient`).

### Medium
- [ ] **No timeout indicator for running requests** — only shows loading spinner with no elapsed time.
- [ ] **Request history is stored in Zustand (localStorage) only, never synced to `/api/history`** (`collectionsStore.ts:439-441`). The `addToHistory` only updates local state, never calls the API.
- [ ] **API execute route uses `optionalAuth` but the frontend always sends auth token anyway** (`apps/api/src/routes/execute.ts:1`). This is acceptable but means anonymous users can't execute requests through the API.

## Environments & Variables

### High
- [ ] **Variable interpolation uses identical regex patterns for env and global variables** (`apps/web/src/stores/workspaceStore.ts:135-136`). Both `envPattern` and `globalPattern` are `/\{\{([^}]+)\}\}/g`. The function interpolates environments first, then globals — if a variable exists in both, the global value overwrites the env value, which is incorrect behavior.
- [ ] **Environment delete is permanent (no soft-delete/trash)** (`apps/api/src/routes/environments.ts`). Unlike collections which have soft-delete with 30-day trash retention, environments are hard-deleted immediately.

### Medium
- [ ] **No validation that variable keys are non-empty** — both API and UI accept empty string keys in variables.
- [ ] **No "Add Environment" button visible in workspace page** despite the Sidebar having environment list.

## Security

### Critical
- [ ] **JWT_SECRET and JWT_REFRESH_SECRET fallback to hardcoded secrets** (`apps/api/src/utils/jwt.ts:4-5`). If env vars are not set, falls back to `'your-super-secret-jwt-key-change-in-production'` which is publicly known.
- [ ] **Rate limiter (1000 requests per 15 minutes) applies globally, not per user/IP** (`apps/api/src/index.ts:46-51`). All users share the same limit.

### High
- [ ] **No HTTPS in development** — all traffic over HTTP/WS.

### Medium
- [ ] **CORS origin defaults to `http://localhost:3000`** (`apps/api/src/index.ts:35`). While acceptable for development, this is a hardcoded fallback.
- [ ] **Upload endpoint (`/api/upload`) has no file type validation** — accepts any file up to 10MB.
