## Login & Register Pages

### Critical
- [ ] **Password fields missing `autocomplete` attributes** — Both login (`apps/web/src/app/(auth)/login/page.tsx:90`) and register (`apps/web/src/app/(auth)/register/page.tsx:96`) password inputs lack `autocomplete="current-password"` / `autocomplete="new-password"`. Browser console warns about this. **Fix:** Add `autoComplete="current-password"` and `autoComplete="new-password"` respectively.

### High
- [ ] **No password visibility toggle** — Password fields have no show/hide button, making it difficult for users to verify typed passwords on register. **Fix:** Add an icon button inside the Input component to toggle `type="text"` / `type="password"`.

### Medium
- [ ] **No "Forgot Password" link on login page** — Users have no way to recover their password. **Fix:** Add a `<Link>` below the password input or next to the Sign In button.

- [ ] **Error state lacks persistent visual feedback** — Error banner uses `bg-red-500/10 border-red-500/20` but disappears on re-focus. No inline field-level validation errors.

### Low
- [ ] **Missing favicon.ico** — Console shows 404 for `/favicon.ico`. **Fix:** Add a favicon to `apps/web/public/`.

## Workspace Layout (Main Page)

### Critical
- [ ] **Zero mobile responsiveness — workspace broken at 375px** — At mobile viewport (375x812), the sidebar (280px + 48px icon rail = 328px) consumes ~87% of the width, leaving only ~47px for the main content area. The TopBar, RequestTabs, and main content are crushed. No media queries or collapse logic exists for mobile. **Fix:** Implement responsive sidebar that auto-collapses on viewports < 768px, or use a mobile drawer pattern. File: `apps/web/src/app/(app)/workspace/page.tsx`.

### High
- [ ] **401 error on workspace load for anonymous users** — Guest users see 401 errors in console because `/api/workspaces` rejects unauthenticated requests. The `loadInitialData` function at `page.tsx:92-108` doesn't handle this gracefully — the workspace shows "Workspace" placeholder with no data. **Fix:** Skip API calls for anonymous users or handle 401 by falling back to local state.

- [ ] **Tablet layout is cramped** — At 768px, the sidebar (280px) takes 36% of the width, leaving too little for the request builder. The TabBar items crowd and overflow. **Fix:** Reduce sidebar default width or auto-collapse at tablet.

### Medium
- [ ] **Collection panel and environment panel are fixed 500px wide** — `w-[500px]` on `page.tsx:842` and `page.tsx:865` is too wide for tablet. No responsive breakpoint. **Fix:** Use `w-[500px] lg:w-[400px] md:w-[300px]` or a percentage with max-width.

- [ ] **Split pane drag handles lack `aria-valuenow`/`aria-orientation`** — The horizontal (`page.tsx:753`) and vertical (`page.tsx:811`) splitter divs lack ARIA slider roles.

- [ ] **Console logs `Failed to load initial data` error visible in console** — User-facing error not shown in UI.

### Low
- [ ] **No page `<title>` update per workspace** — Title always shows "Runner - API Development Platform".

## Sidebar

### High
- [ ] **Icon-only buttons lack `aria-label`** — The collapse button (`Sidebar.tsx:481`), icon rail buttons (`:493`), expand/collapse chevrons all lack accessible labels. **Fix:** Add `aria-label` to all icon-only buttons.

- [ ] **"New" dropdown close on blur is fragile** — Uses `onBlur` with `setTimeout` (`Sidebar.tsx:526`), causing poor UX. **Fix:** Use a proper click-outside listener.

### Medium
- [ ] **No keyboard navigation for collection/folder tree** — Users cannot arrow-key through collections. No `role="tree"` or `role="treeitem"` ARIA attributes.

- [ ] **Search input lacks `aria-label="Search collections"`** — `Sidebar.tsx:626` has only a placeholder.

- [ ] **Collection import error toast covers content** — The absolute-positioned error toast (`Sidebar.tsx:641`) at the bottom can overlap the resize handle.

- [ ] **Resize handle `w-1` is too thin for mouse interaction** — 1px is hard to target. **Fix:** Use `w-1` but with a larger invisible hit area using `::before` pseudo-element.

- [ ] **HTTP method colors in sidebar don't match RequestBuilder** — Sidebar uses CSS classes (`.http-method.get` → `#61affe`), while RequestBuilder uses inline Tailwind (`text-green-400`). Inconsistent color scheme.

### Low
- [ ] **Import button `<label>` wraps hidden `<input>` but lacks `role="button"`** — Not announced correctly by screen readers.

- [ ] **No empty state illustration for collections/history** — Only text "No history yet" / "No environments".

## Request Builder

### High
- [ ] **`Buffer.from(response.body).toString('base64')` in ResponseViewer crashes in browser** — `apps/web/src/components/response/ResponseViewer.tsx:227` uses `Buffer` which is not available in browser context. Image preview mode will throw a ReferenceError. **Fix:** Use `btoa()` and `TextEncoder` instead.

### Medium
- [ ] **Method selector has hardcoded width 90px** — `RequestBuilder.tsx:228` uses `style={{ width: '90px' }}`. Longer method names don't fit. **Fix:** Use `min-w-[90px]` or `w-auto`.

- [ ] **No variable autocomplete in URL input** — The URL bar (`RequestBuilder.tsx:238`) doesn't show variable suggestions. Requires users to type `{{` manually.

- [ ] **Save dropdown trigger button has no ARIA attributes** — No `aria-haspopup`, `aria-expanded`, or `aria-label`.

- [ ] **Send button dropdown split has poor UX** — The `<ChevronDown>` on the Send button (`RequestBuilder.tsx:279`) creates a confusing split-button pattern without clear affordance. **Fix:** Use a proper split-button component or a separate dropdown arrow.

- [ ] **Active method colors inconsistent with rest of app** — Uses `text-green-400` for GET but sidebar uses `#61affe`.

### Low
- [ ] **GraphQL tab creates duplicate requests** — `handleCreateNew('graphql')` at `page.tsx:189-200` calls `handleNewRequest()` first, then replaces the last tab, causing an unnecessary duplicate.

- [ ] **No "Prettify" / "Format" button for raw JSON body** — Users must manually format their JSON.

- [ ] **Binary file upload shows filename but still needs to upload on send** — No actual file handling beyond name display.

## Global / Cross-Cutting

### High
- [ ] **Hardcoded colors instead of Tailwind theme tokens** — Most components use `bg-[#262627]`, `bg-[#3d3d3d]`, `text-gray-400` etc. instead of the defined tokens in `tailwind.config.js` (e.g., `sidebar-bg`, `panel-border`). This makes theming very difficult. **Fix:** Replace with theme tokens systematically.

- [ ] **Focus-visible rings missing on many interactive elements** — Scrollbar, dropdown items, sidebar links, and many buttons lack `focus-visible:ring-2`. **Fix:** Add focus ring utility classes to all interactive elements.

### Medium
- [ ] **`globals.css` has broken `@layer components`** — References `bg-primary-500`, `bg-panel-bg` etc. but these tokens don't resolve correctly (primary-500 is `#0ea5e9`, not the accent `#ff6b35`). These classes are unused but misleading.

- [ ] **No prefers-reduced-motion support** — Animations like `animate-spin`, `transition-colors duration-200` should respect `@media (prefers-reduced-motion: reduce)`.

- [ ] **Google Fonts import causes render-blocking and FOUT** — `globals.css:5` loads Inter and Fira Code from Google Fonts with no `font-display: swap` fallback defined in CSS.

### Low
- [ ] **Custom scrollbar styles only work in WebKit browsers** — Firefox and other browsers see default scrollbars.

- [ ] **`aria-hidden` not applied to decorative icons** — Many Lucide icons in buttons are decorative but not hidden from screen readers.
